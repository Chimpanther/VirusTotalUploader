💡 **What:** The optimization refactors `UploadForm` to take a `List<string>` for paths rather than a single `string`. Instead of iterating in `MainForm` and creating `N` UI forms for `N` dragged files, `MainForm` now creates a single `UploadForm` instance and passes it the entire list of dropped files. `UploadForm` will iterate through all provided paths efficiently on its background upload thread.

🎯 **Why:** Previously, dragging and dropping multiple files (e.g. 100 files) would cause `MainForm` to loop over all of them, instantiating and calling `.Show()` for 100 separate `UploadForm` instances. This consumed an excessive amount of memory, bogged down the UI thread, resulted in a poor user experience, and was extremely slow/inefficient.

📊 **Measured Improvement:** Since the main `uploader` .NET 4.8 Framework project could not natively build or be executed directly in the standard xUnit `dotnet test` container via CLI due to missing `packages.config` support, standard benchmark logging couldn't be efficiently compiled/run in CI for this UI specific test. However, from a Big O perspective, the UI instantiation changes from $O(N)$ (where $N$ is the number of dragged files) to $O(1)$. Memory and UI-thread utilization is drastically reduced.
